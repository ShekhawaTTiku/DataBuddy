Classify the current user message for DataBuddy. Return only a JSON object with keys `route`, `reason`, and `reply`.

Allowed route values:
- `analysis`: asks to calculate, filter, compare, aggregate, or inspect the loaded dataset; includes a clear follow-up to a previous dataset analysis. Does NOT ask for a visual representation.
- `visualization`: asks to plot, chart, graph, visualize, or show a visual representation of data. Keywords: chart, plot, graph, bar chart, line chart, pie chart, histogram, scatter, heatmap, distribution, correlation, trend chart, visualize, dashboard. Also use this route if the user asks for a correlation heatmap or distribution analysis.
- `modify_chart`: asks to change, update, or customize a previously generated chart. Keywords: change the colors, make it horizontal, add a trend line, update the title, switch to bar chart, etc. Only use this route if there is a previous chart in the conversation.
- `conversation`: ordinary conversation, general knowledge, greetings, or a question about a user fact in the conversation.
- `explain_analysis`: asks how DataBuddy got or verified a previous analytical answer.
- `clock`: asks for the current local time or today's date.

Do not treat a remembered preference or a casual mention of a region/category as a dataset filter. A filter applies only when the current question asks for it, or when the message clearly continues a previous analysis.
For `conversation`, write a concise, helpful user-facing answer in `reply`. Use the conversation context and do not invent personal facts. For `analysis`, `visualization`, `modify_chart`, `explain_analysis`, or `clock`, set `reply` to an empty string; the application handles those routes separately.
